How the agents & stop-check govern each round

Planner

Reads the topic and target keyword once, produces a title, audience, keyword strategy and section outline that every later agent treats as the brief.

Executor

Writes draft v0 from the Planner's outline — the seed the improvement loop will repeatedly refine.

Evaluator

Re-scores the current draft every round against a fixed rubric (SEO, structure, depth, engagement), returning a fresh 0–100 score — never reused from a prior round.

Critic

Reads that round's evaluation and pinpoints the 3 most consequential weaknesses with concrete fixes — not a re-score, a diagnosis.

Memory Manager

Extracts durable lessons from the round (patterns that keep recurring) and carries them forward so the Improver doesn't relearn the same fix twice.

Safety Monitor

Screens the draft for unsupported claims, overpromising, or brand-unsafe language each round, independent of quality scoring.

Improver

Rewrites the full draft using this round's evaluation + critique + safety notes + accumulated memory. Its output becomes next round's input to the Evaluator — the loop's return edge.

Final Reviewer

Runs once, only after a stop condition fires. Gives a publish decision and rationale referencing the full round history and the exact reason the loop ended.

Stop-check, evaluated in this order every single round
  1. Plateau check — once at least two rounds have a score delta on record, if both of the last two round-over-round deltas are smaller than the configured plateau delta, the loop stops: more iteration isn't buying quality.
  2. Threshold check — if the plateau didn't fire, and this round's score has reached the target set at interview, the loop stops: quality bar met.
  3. Hard iteration cap — a safety fallback only. If neither check has fired by the configured max round count, the loop stops anyway so a stubborn draft can't run forever.

Whichever check fires first ends the round loop and hands the draft to the Final Reviewer, which is why the round indicator reads "Round N — checking stop condition…" rather than "Round N of M": M isn't decided until the run is over.

Architecture overview & what to build next
Architecture
  • Single HTML file, vanilla JS orchestrator, no framework or build step — every agent call is a direct fetch to /v1/messages with a role-specific system prompt.
  • State threads forward explicitly: each Improver call receives the exact evaluation + critique + safety + memory text from that same round, never a summary written by this app.
  • The loop is a real while with a runtime break — the stop-check function is the only thing deciding round count.
  • Per-call retry with exponential backoff; a failed run preserves history so a "Resume" action can re-enter the loop at the exact round it stopped on.
Extension ideas
  • Add a Fact-Checker agent that runs web search tool calls against Safety Monitor flags before Improver rewrites.
  • Persist full run history to localStorage/IndexedDB and diff drafts round over round.
  • Swap the single-score rubric for the weighted multi-dimension rubric (SEO / structure / readability / originality) and plot each dimension's own trend line.
  • Parallelize Critic and Safety Monitor calls (they're independent) to cut wall-clock time per round.
  • Add a human-in-the-loop gate: pause after Critic and let a person approve or edit before Improver runs.
Further prompts for building more advanced autonomous systems
"Add a Fact-Checker agent that calls a web search tool and blocks the loop from stopping if Safety Monitor flags are still unresolved."
