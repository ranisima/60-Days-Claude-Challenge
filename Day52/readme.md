Step-by-Step Guide
1. Open your Day 51 Claude conversation
Open Claude.
Find your Day 51 capstone conversation.
Continue in the same thread.
Do not start a new conversation.
2. Paste today's System Design prompt
Copy the Day 52 System Design prompt.
Paste it into the Day 51 conversation.
Send it to Claude.
3. Confirm Claude re-reads yesterday's work

Before Claude proposes anything, confirm that it re-reads:

 PRD
 Implementation Blueprint
 Pitch Deck

Make sure today's system design is based on the approved scope from yesterday.

4. Set up the GitHub repository if needed

If you don't already have a project GitHub repository:

Ask Claude for the exact numbered setup instructions.
Create the repository.
Clone it locally.
Set up the initial project structure.
Follow Claude's steps exactly.
Take a screenshot after each major step.
Keep the screenshots for your Day 52 documentation.

If the repository already exists, confirm that it is ready and continue.

5. Review the technology stack

Work through each section with Claude:

 Frontend
 Backend
 Database
 Authentication
 AI model/API
 Hosting
 Other tools/services

For every technology choice, ask Claude to explain why it fits your actual project requirements.

Check the choices against:

User stories
Expected users
Project complexity
Budget
Security
AI requirements
Development timeline
6. Review the Mermaid system architecture

Review the complete Mermaid architecture.

Check:

 Component diagram
 Data flow
 Request lifecycle
 Frontend/backend communication
 Database interaction
 AI interaction
 Authentication
 External services
 Error handling

Make sure the architecture isn't unnecessarily complicated.

7. Review the database design

Review:

 Tables/collections
 Fields
 Primary keys
 Foreign keys
 Relationships
 Constraints
 Indexes, if needed

Compare the database design against every user story in yesterday's PRD.

Confirm that every user story has the data it needs.

8. Review the complete API design

Review every v1.0 endpoint.

For each endpoint, check:

 Purpose
 HTTP method
 URL
 Request
 Response
 Validation
 Authentication
 Authorization
 Success cases
 Error cases

Make sure no unnecessary APIs or out-of-scope features have been added.

9. Review the user flow and wireframes

Review:

 User-flow diagram
 Screen-flow diagram
 Low-fidelity wireframes
 Navigation

Trace the complete journey:

User enters → signs in → performs the main task → receives result → completes the workflow

Make sure every important PRD user story is represented.

10. Review the project folder structure

Review Claude's proposed folder structure.

Understand the purpose of every major folder.

For example:

project/
├── docs/
├── src/
├── components/
├── pages/
├── services/
├── api/
├── database/
├── tests/
└── ...

Use Claude's actual project-specific structure rather than copying this example.

Confirm that the structure is:

 Easy to understand
 Appropriate for the tech stack
 Scalable enough
 Not unnecessarily complicated
11. Complete the Day 3 readiness check

Confirm:

 Remaining Blueprint is realistic
 No scope creep
 No unnecessary features
 Database supports all approved user stories
 APIs support the required workflows
 UI flow is implementable
 Folder structure is ready
 Implementation can start tomorrow

If Claude recommends simplifying anything, simplify it now.

12. Generate the five deliverables

Ask Claude to generate the final versions of:

ARCHITECTURE.md
SCHEMA.md
API.md
UI-WIREFRAMES.md
PROJECT-STRUCTURE.md

Download/save the actual Markdown files.

Do not rely only on screenshots.

13. Update the Implementation Blueprint if required

If today's decisions changed yesterday's Blueprint:

 Ask Claude to update the Blueprint
 Generate the final version
 Download/save it

If nothing changed, no updated Blueprint is necessary.

14. Commit the documents to the project repository

In your project GitHub repository:

Open the docs location created by Claude.
Add the five deliverables.
Add the updated Blueprint if applicable.
Check the files.
Commit the changes.
Push to GitHub.

Example commit message:

docs: complete system design architecture

Copy the project repository commit URL for your records.
